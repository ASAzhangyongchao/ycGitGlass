## 1. 安装与迁移

### 1.1 直接安装现成应用

适用：Apple Silicon（M 系列）Mac，macOS 26 及以上。

1. 解压 `GitGlass-1.2.0-macOS26.zip`。
2. 把 `GitGlass.app` 拖进「应用程序」（也可放任意目录）。
3. 首次打开若提示「无法验证开发者」，在终端执行：

   ```bash
   xattr -cr /Applications/GitGlass.app
   ```

   或在 Finder 中右键应用 → 「打开」→ 确认。应用是 ad-hoc 本地签名，这是正常现象，不涉及联网上传。
4. 双击启动，或使用 `open /Applications/GitGlass.app`。

### 1.2 在另一台 Mac 从源码构建

适用：Intel Mac、想换架构、或目标机器系统环境不同。

```bash
cd GitGlass-1.2.0-macOS26
xcode-select --install          # 已有 Xcode 26 可跳过
chmod +x scripts/build-app.sh
./scripts/build-app.sh          # 自动编译当前机器架构
open dist/GitGlass.app
```

构建要求：Swift 6.2 / macOS 26 SDK。脚本会打印目标架构。若报 `sandbox-exec: Operation not permitted`，说明当前环境不允许 SwiftPM 嵌套沙箱，脚本已经带上了 `--disable-sandbox`，按脚本执行即可。

### 1.3 迁移个人配置

| 想带过去的东西 | 操作 |
|---|---|
| 仓库列表、自定义平台、密钥归类 | 复制 `~/Library/Application Support/GitGlass/state.json` 到新机器同路径 |
| SSH 密钥 | 应用**不会**打包密钥。请自行安全迁移 `~/.ssh/` 下的密钥对，或在新机器重新生成并添加公钥 |
| SSH Host 规则 | 到新机器的「密钥」页点「写入 ~/.ssh/config」即可重新生成 |
| 仓库代码 | 用 git 自己管理，与应用无关 |

### 1.4 卸载

删除 `GitGlass.app`；若要连配置一起清除，再删除 `~/Library/Application Support/GitGlass/`。应用不写系统级服务、不装后台守护进程、不写登录项。

## 2. 认识界面

窗口分三块：

| 区域 | 内容 |
|---|---|
| 左侧边栏 | 仓库列表（添加 / 扫描 / 新建 / 克隆）、当前选中仓库 |
| 顶栏 | 仓库名、当前分支、领先/落后、分支切换菜单、拉取 / 推送 / 手动刷新、上次刷新时间 |
| 中间内容区 | 六个页签：工作台、提交、历史、储藏、远程源、密钥 |

**六个页签的定位**

| 页签 | 什么时候用 |
|---|---|
| 工作台 | 每天先看一眼：有多少改动、要不要拉取、最近提交了什么 |
| 提交 | 勾选文件、看 diff、暂存、写说明、提交 |
| 历史 | 找某次提交、看分支图、遴选 / 还原 / 打标签 |
| 储藏 | 临时收起改动、恢复储藏、管理标签、中止冲突中的遴选 |
| 远程源 | 维护 remote 地址、抓取 / 拉取 / 推送 |
| 密钥 | 为每个平台生成和维护 SSH 密钥、测试连接 |

### 2.1 屏幕顶部菜单栏

安装后屏幕最上方会有两处「码牛」：

| 位置 | 内容 |
|---|---|
| 菜单栏左侧 | 应用菜单「码牛」，含「关于 码牛 MooGit」以及 Git 菜单（刷新 / 拉取 / 推送 / 储藏 / 六个页面快捷键） |
| 菜单栏右侧 | 常驻分支小图标。点开可看当前仓库名、改动数与分支，直接执行「打开主窗口 / 手动刷新 / 拉取 / 推送 / 退出」；即使关掉主窗口也保留 |

主窗口页头还有一条玻璃品牌条：小牛 logo + 名称 + 版本徽标 + 当前仓库 / 分支；窗口标题栏显示「码牛 MooGit」。若 Dock 图标没换成小牛，退出后重新打开，必要时执行 `killall Dock` 刷新图标缓存。

**顶栏的刷新按钮很重要**：应用不会自动轮询。改完代码后，点一下「刷新」（或按 `⌘R`），或切一次仓库 / 分支，数据才会更新。

## 3. 工作台

一屏看完全天状态：

- 顶部一句话总结：`仓库名 有 N 个改动，M 个已暂存`。
- 六个统计块：未暂存改动、已暂存、领先/落后远程、储藏数、标签数、已加载提交数。
- 「今天要做的事」：按顺序给出拉取 → 查看并暂存 → 一键提交全部并推送，以及手动刷新、查看历史。
- 「最近提交」：最近 5 条，点任意一条会跳到历史页并打开右侧详情。
- 首次使用会出现「三步上手」卡片，点「知道了」后不再显示。
- 如果遴选 / 还原 / 合并处于进行中（通常是冲突），顶部会出现黄色横幅，点「去处理」跳到储藏页。

> 「一键提交全部并推送」在没有写提交说明时，会自动生成 `chore: 更新 N 个文件`，适合日常小改动。需要规范说明时请到「提交」页手写。

## 4. 提交代码

### 4.1 标准流程

1. 在「提交」页看「代码变更」列表，支持两种视图：
   - **列表**：每行有勾选框、状态徽标、文件名与目录，点文件名在右侧看 diff。
   - **目录树**：按目录折叠，路径层级一眼可见，适合大仓库。
2. 勾选要提交的文件 → 点「暂存所选」（或「暂存全部」）。
3. 写一句提交说明。可以点 `feat` / `fix` / `docs` / `refactor` / `test` / `chore` 快捷插入 Conventional Commits 前缀。
4. 点「提交」或「提交并推送」。首次推送会自动加 `-u` 建立上游关联。

### 4.2 状态徽标

| 徽标 | 含义 |
|---|---|
| 新增 | 未跟踪的新文件 / 已暂存的新增 |
| 修改 | 内容被改动 |
| 删除 | 文件被删除 |
| 重命名 | git 检测到重命名 |
| 冲突 | 合并或遴选产生的冲突，需要先解决 |
| 已加 | 已加入索引 |

### 4.3 差异预览

点文件名后右侧显示逐行 diff：绿色为新增、红色为删除、紫色为 hunk 标记。未跟踪文件会退化为文本预览（超过 256 KB 或二进制文件会给出提示，不强行读取）。

### 4.4 其他操作

| 操作 | 说明 |
|---|---|
| 取消暂存 | 把已暂存文件移回未暂存；空仓库（首次提交前）会自动用 `git rm --cached` |
| 丢弃所选改动 | 危险操作，二次确认；把文件还原到最近一次提交或暂存的状态 |
| 储藏当前改动 | 临时收起全部改动，切分支或遴选前使用；到「储藏」页恢复 |

## 5. 历史、遴选与提交详情

### 5.1 彩色分支轨道

左侧的彩色轨道由 `git log --graph` 重绘：不同颜色代表不同分支 lane，圆点是提交，竖线 / 斜线 / 横线是分支与合并关系。鼠标悬停可看原始图形字符。相比纯 ASCII，分支走向更直观。

### 5.2 搜索

搜索框输入时**即时过滤已加载的记录，不执行任何 git 命令**，所以打字再快也不卡。

| 输入 | 效果 |
|---|---|
| `登录` | 在提交说明、作者、邮箱、hash、标签里做不区分大小写的本地过滤 |
| `author:张三` | 只按作者过滤 |
| `message:修复` | 只按提交说明过滤 |
| `hash:a1b2c3` | 按提交号过滤 |
| `file:README.md` | 按文件搜索完整历史（需点「深度搜索」） |
| `since:2026-01-01` / `until:2026-06-01` | 日期范围（需点「深度搜索」） |
| 「全部分支」勾选 | 读取所有分支的提交，勾选后会触发一次刷新 |

「深度搜索」会真正执行 `git log`，最多取 500 条，适合查已加载范围之外的历史。

### 5.3 提交详情面板

点历史列表里任意一条，右侧滑出详情面板：

- 完整提交号（可复制）、作者、邮箱、提交时间、提交者、父提交、标签 / 分支引用。
- 统计：文件数、新增行、删除行。
- 提交说明正文。
- 操作：**遴选**、**还原**、**打标签**、复制 hash。
- 「变更文件」按目录折叠，点文件在面板底部显示该提交里的逐文件 diff。

### 5.4 遴选（Cherry-pick）

借鉴 Sourcetree：把某一条别的分支上的提交，「复制」成当前分支的一条新提交，原提交保持不变。

1. 在历史页找到目标提交（必要时勾「全部分支」或深度搜索）。
2. 打开详情 → 点「遴选」→ 确认。
3. 成功后自动刷新一次，新提交出现在当前分支历史顶部。

> 若内容冲突，工作台顶部出现提示，「储藏」页会展开冲突处理面板（见 5.5）。
> 小知识：Git 是内容寻址的，若父提交、文件树、作者和时间戳完全一致，遴选产生的新提交可能与原提交 hash 相同，这是正常现象。

### 5.5 冲突可视化处理

遴选 / 还原 / 合并 / 变基留下未解决状态时，工作台显示黄色提示，「储藏」页展开专门的冲突面板：

| 元素 | 作用 |
|---|---|
| 冲突文件列表 | 显示文件名与完整路径，可一键在 Finder 中打开仓库目录 |
| 采用当前分支 | `git checkout --ours`，保留你这一侧的内容 |
| 采用对方 | `git checkout --theirs`，用被遴选提交的内容 |
| 已手动解决 | 自己在编辑器里删掉 `<<<<<<<` 标记后，点此把文件标记为已解决 |
| 继续遴选 / 还原 | 全部冲突清空后可用，执行对应的 `--continue` 完成操作 |
| 中止当前操作 | 执行 `--abort`，工作区回到操作前 |

每处理一个文件都会自动刷新一次，列表实时变短；**没有进行中的操作时，冲突列表不会执行任何 git 命令**。

### 5.6 还原（Reverse commit）

生成一条**反向提交**来撤销历史改动，不改写已有历史，适合已经推送出去的提交。操作同样在详情面板，危险操作会二次确认。

## 6. 储藏与标签

### 6.1 储藏

| 操作 | 说明 |
|---|---|
| 储藏当前改动 | 可写说明、可选是否包含未跟踪文件；储藏后工作区恢复干净 |
| 恢复 | `git stash apply`，保留储藏记录 |
| 恢复并移除 | `git stash pop`，恢复后删除记录 |
| 删除 | 删除单条储藏，二次确认 |

列表显示 `stash@{N}`、说明、来源分支、相对时间。工作区干净时点储藏会明确提示「当前没有可储藏的改动」，不会误报成功。

### 6.2 标签

- 新建标签：填名称，可选附注说明（填了就是附注标签，留空是轻量标签），默认打在当前 HEAD。
- 给历史提交打标签：在历史详情面板点「打标签」。
- 列表显示目标提交短 hash、类型徽标、附注内容；可复制名称、删除本地标签。

### 6.3 中止进行中的操作

遴选、还原、合并、变基若留下未完成状态，页面顶部出现黄色横幅，点「中止当前操作」会执行对应的 `--abort`，回到操作前的工作区。

## 7. 远程源

| 操作 | 说明 |
|---|---|
| 添加远程源 | 填名称（通常 `origin`）和地址，建议用 SSH 地址 |
| 编辑地址 / 重命名 / 复制地址 / 删除 | 每行右侧「操作」菜单，删除会二次确认 |
| 抓取 | `git fetch --prune` |
| 拉取 | `git pull --ff-only`，保持历史线性、避免多余合并提交 |
| 推送 | 首次自动建立上游关联；被拒绝时提示先拉取 |

一个仓库可同时配置多个远程源（例如 `origin` 与 `upstream`）。远程源为空时仍可正常本地提交。

## 8. 多平台 SSH 密钥

内置平台：GitHub、GitLab、Gitee、Bitbucket、CODING，也可添加自建平台（填名称和域名）。

### 8.1 首次配置流程

1. 「密钥」页找到平台卡片 → 点「生成密钥」。
2. 可选填邮箱（只写进公钥注释）、可选设置密码短语（不会被保存或写日志）。
3. 生成 ED25519 密钥对：`~/.ssh/id_ed25519_<平台>`，私钥权限自动设为 `600`。
4. 点「复制公钥」→ 粘贴到平台账号的 SSH Keys 设置页。
5. 点「测试连接」确认认证通过。
6. 多平台多账号时点「写入 ~/.ssh/config」，为每个平台生成独立 Host 规则（`IdentitiesOnly yes`），避免串号。

### 8.2 其它能力

| 能力 | 说明 |
|---|---|
| 指纹 | 显示 `SHA256:...`、密钥类型、位数、注释 |
| 权限检查 | 私钥权限过宽会显示「权限过宽」并提供一键修复 |
| 归类 | 自动按文件名 / 注释推断平台，可手动改 |
| 仅公钥 | 只有公钥没有私钥时会标注，无法用于认证 |
| 写入 SSH 配置 | 只替换 `# >>> GitGlass managed >>>` 标记块，用户手写配置原样保留；首次写入自动备份为 `config.gitglass.bak` |

> 应用只读取公钥内容，**从不读取、展示、复制或记录私钥文件内容**。

## 9. 刷新机制与性能

这是本应用最刻意的设计：**不按固定时间刷新**。

| 会触发刷新 | 不会触发刷新 |
|---|---|
| 应用启动（一次） | 定时器 / 轮询 |
| 点顶栏「手动刷新」或 `⌘R` | 应用切到前台 / 后台 |
| 切换仓库 | 文件系统变化监听 |
| 切换分支（含新建、删除） | 打字输入（历史搜索是纯内存过滤） |
| 任意写操作成功或遴选冲突失败后 | 窗口获得焦点 |
| 点「深度搜索」、勾选「全部分支」 | 网络状态变化 |

一次刷新会**并行**读取状态、分支、历史、远程源、储藏、标签、密钥，避免串行等待；冲突文件列表只在检测到「操作进行中」时才额外读取，正常仓库零额外进程。空闲时没有后台任务、没有循环动画，实测应用 footprint 约 38 MB 且长时间不增长。动画全部由状态变化触发，支持系统「减弱动态效果」与「降低透明度」。

## 11. 故障排查

| 现象 | 原因与处理 |
|---|---|
| 打开应用提示「无法验证开发者」 | ad-hoc 签名，执行 `xattr -cr /Applications/GitGlass.app` 或右键「打开」 |
| 添加文件夹提示「不是 Git 仓库」 | 选中的目录里没有 `.git`；用「新建仓库」初始化，或重新选对目录 |
| 推送被拒绝 | 远程有别人的新提交，先点「拉取」，再推送 |
| SSH 认证失败 | 到「密钥」页确认公钥已添加到平台账号、私钥存在且权限为 600，点「测试连接」 |
| 提交按钮是灰的 | 需要有已暂存文件 + 非空提交说明 |
| 切分支失败提示有未提交改动 | 先提交或储藏当前改动，再切换 |
| 遴选后出现冲突面板 | 用「采用当前分支 / 采用对方 / 已手动解决」逐个处理，再点「继续」；或直接「中止当前操作」 |
| 数据看起来没更新 | 点顶栏「刷新」，或切一次仓库 / 分支；应用故意不自动轮询 |
| 找不到刚打的标签 / 新储藏 | 点一次刷新，写操作成功会自动刷新，手动执行 git 命令后需手动刷新 |
| Intel Mac 打不开现成 .app | 该应用是 arm64，按 1.2 用源码在目标机器重建 |
| 构建报 `sandbox-exec: Operation not permitted` | 使用脚本里的 `--disable-sandbox`，或安装完整 Xcode |

错误提示条会给出中文原因与修复建议，展开「查看原始信息」可看到 git 的原始 stderr 便于深入排查。

## 12. 隐私与安全

| 项目 | 做法 |
|---|---|
| 命令执行 | 参数按数组传递、路径用 `--` 分隔，绝不拼接 shell 字符串 |
| 私钥 | 不读取内容、不复制到剪贴板、不写日志、不随分发包传播 |
| 日志 | 系统 `os.Logger` 结构化 JSON，私钥块与 token 参数会被脱敏 |
| 网络 | 只有 `git fetch/pull/push/clone` 与 `ssh -T` 测试连接会联网；不做统计上报 |
| 配置修改 | `~/.ssh/config` 只改带标记的管理块，首次自动备份 |
| 凭据 | 无账号密码存储、无令牌落在磁盘；认证完全交给系统 git / ssh-agent |
| 危险操作 | 删除远程源 / 标签 / 储藏、丢弃改动、遴选、还原均有二次确认 |

## 13. 开发者说明

### 13.1 分层

```
Views（SwiftUI）
   ↓ 只消费状态，不含业务逻辑
AppState（@Observable @MainActor，刷新编排）
   ↓
GitService / SSHKeyService（领域服务，不依赖 UI 类型）
   ↓
CommandRunner（Process，参数数组 + 临时文件输出 + 超时保护）
```

- 持久化：`~/Library/Application Support/GitGlass/state.json`，不用数据库。
- 错误：`AppError` 类型化 + 中文 `friendlyMessage` / `recoverySuggestion` / `rawDetail`。
- 配置：`AppConfig` 集中管理外部命令路径与平台预设，启动时校验快速失败。
- 并发：Swift 6 严格模式；`AppState` 用 continuation 排队避免刷新被静默丢弃；密钥指纹、刷新数据均并行拉取。

### 13.2 自检

```bash
swift run --disable-sandbox GitGlassSelfTest
```

在临时 Git 仓库与临时 SSH 目录上跑 129 项断言（12 个分节），覆盖：状态 / 暂存 / 提交 / 历史搜索 / 遴选 / 还原 / **冲突检测与选边 / 继续 / 中止** / 储藏 / 标签 / 提交详情 / 中文空格路径 / 远程源 / 错误映射 / 持久化 / 密钥生成与权限 / SSH config 幂等与备份 / 命令超时与并发 / 模型契约。不触碰用户真实 `~/.ssh`。

### 13.3 扩展点

- 新增 git 能力：在 `GitService` 加方法 → `AppState` 加 `mutate` 包装 → 对应页面加按钮。
- 新增平台：在 `AppConfig.defaultPlatforms` 加预设，或在应用内「添加自建平台」。
- 新增页面：在 `AppTab` 加 case → `RootView` 的 switch 里加视图。
- 刷新策略：只在 `AppState.refresh` / `mutate` 里触发，请勿引入 Timer。
