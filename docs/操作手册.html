01 安装与迁移

直接在 Apple Silicon Mac 安装

  1. 解压 GitGlass-1.3.0-macOS26.zip，把 GitGlass.app 拖进「应用程序」。
  2. 若提示「无法验证开发者」，执行 xattr -cr /Applications/GitGlass.app，或右键 → 「打开」。
  3. 运行 open /Applications/GitGlass.app。
现成 .app 是 arm64 架构、ad-hoc 本地签名。仅装 Command Line Tools 的环境无法构建通用二进制（缺 XCBuild.framework），所以 Intel Mac 请走源码重建。

在另一台 Mac 从源码构建

cd GitGlass-1.3.0-macOS26
xcode-select --install          # 已有 Xcode 26 可跳过
chmod +x scripts/build-app.sh
./scripts/build-app.sh          # 自动编译当前机器架构
open dist/GitGlass.app

脚本中的 --disable-sandbox 用于受管环境不允许 SwiftPM 嵌套沙箱的情况，普通 Xcode 环境保留也无害。

迁移个人配置

数据位置 / 操作
仓库列表、自定义平台、密钥归类复制 ~/Library/Application Support/GitGlass/state.json 到新机器同路径
SSH 密钥应用不会打包密钥；请自行安全迁移 ~/.ssh/，或在新机器重新生成并添加公钥
SSH Host 规则新机器「密钥」页点「写入 ~/.ssh/config」重新生成
卸载删除 GitGlass.app；想清配置再删上述 state.json

03 工作台

  • 一句话总结当前仓库状态：仓库名 有 N 个改动，M 个已暂存。
  • 六个统计块：未暂存、已暂存、领先/落后、储藏数、标签数、已加载提交数。
  • 「今天要做的事」按推荐顺序列出拉取 → 查看并暂存 → 一键提交全部并推送。
  • 最近 5 条提交，点任意一条跳到历史页并打开右侧详情。
  • 遴选 / 还原 / 合并进行中时，顶部出现黄色横幅，点「去处理」跳转。
「一键提交全部并推送」在没有说明时自动生成 chore: 更新 N 个文件，适合日常小改动；需要规范说明请到「提交」页手写。

04 提交代码

标准流程

  1. 在「代码变更」里选列表视图或目录树视图（大仓库推荐目录树）。
  2. 勾选文件 → 「暂存所选」或「暂存全部」。
  3. 写一句说明，可点 feat / fix / docs / refactor / test / chore 快捷插入前缀。
  4. 点「提交」或「提交并推送」（首次推送自动建立上游关联）。

差异预览与其它操作

功能说明
逐行 diff绿色新增、红色删除、紫色 hunk；未跟踪文件退化为文本预览（超过 256 KB / 二进制会提示）
取消暂存空仓库首次提交前自动改用 git rm --cached
丢弃所选改动危险操作，二次确认
储藏当前改动切分支或遴选前临时收起，到「储藏」页恢复

05 历史、遴选与提交详情

彩色分支轨道

由 git log --graph 用 Canvas 重绘：不同颜色代表不同分支 lane，圆点是提交，竖线 / 斜线 / 横线是分支与合并关系，悬停可看原始图形字符。

搜索语法

输入效果
登录在说明 / 作者 / 邮箱 / hash / 标签里即时本地过滤，不执行 git 命令
author:张三按作者过滤
message:修复按提交说明过滤
hash:a1b2c3按提交号过滤
file:README.md按文件搜索完整历史，需点「深度搜索」
since:2026-01-01日期范围，需点「深度搜索」
勾选「全部分支」读取所有分支提交，触发一次刷新
「深度搜索」真正执行 git log，最多 500 条，用于查已加载范围之外的历史。

提交详情面板

点列表任意一条，右侧滑出详情：完整提交号（可复制）、作者 / 提交者 / 时间 / 父提交 / 引用、文件数与增删行统计、说明正文、操作按钮、按目录折叠的变更文件树、逐文件 diff。

遴选 Cherry-pick（借鉴 Sourcetree）

  1. 找到目标提交（必要时勾「全部分支」或深度搜索）。
  2. 详情面板点「遴选」→ 确认。
  3. 成功后自动刷新，新提交出现在当前分支历史顶部，原提交保持不变。
若内容冲突，工作台出现提示，「储藏」页展开冲突处理面板。Git 内容寻址下，父提交 / 文件树 / 作者 / 时间戳完全一致时，遴选产生的新提交 hash 可能与原提交相同，属正常现象。

冲突可视化处理

操作作用
冲突文件列表显示文件名与完整路径，可一键在 Finder 打开仓库目录
采用当前分支git checkout --ours，保留自己这一侧
采用对方git checkout --theirs，用被遴选提交的内容
已手动解决编辑器里删掉冲突标记后，把文件标记为已解决
继续 / 中止全部解决后执行 --continue；或直接 --abort 回到操作前

每处理一个文件自动刷新一次；没有进行中的操作时，冲突列表不执行任何 git 命令。

还原 Reverse commit

生成一条反向提交撤销历史改动，不改写已有历史，适合已推送的提交。操作同样在详情面板，有二次确认。

06 储藏与标签

操作说明
储藏当前改动可写说明、可选包含未跟踪文件；储藏后工作区干净
恢复git stash apply，保留记录
恢复并移除git stash pop
删除储藏二次确认
新建标签填名称 + 可选附注；给历史提交打标签请到历史详情面板
中止当前操作对遴选 / 还原 / 合并 / 变基执行对应的 --abort
工作区干净时点储藏会明确提示「当前没有可储藏的改动」，不会误报成功。

07 远程源

操作说明
添加 / 编辑 / 重命名 / 删除每行右侧「操作」菜单，删除二次确认；建议用 SSH 地址
抓取git fetch --prune
拉取git pull --ff-only，保持历史线性、避免多余合并提交
推送首次自动建立上游；被拒绝时提示先拉取

一个仓库可同时配置多个远程源（例如 origin 与 upstream）。远程源为空时仍可正常本地提交。

08 多平台 SSH 密钥

内置 GitHub、GitLab、Gitee、Bitbucket、CODING，也可添加自建平台。

首次配置流程

  1. 平台卡片点「生成密钥」，可选填邮箱与密码短语（不会被保存或写日志）。
  2. 生成 ED25519 密钥对 ~/.ssh/id_ed25519_<平台>，私钥权限自动 600。
  3. 点「复制公钥」粘贴到平台账号的 SSH Keys 页面。
  4. 点「测试连接」确认认证通过。
  5. 多平台多账号点「写入 ~/.ssh/config」生成独立 Host 规则，避免串号。
应用只改 # >>> GitGlass managed >>> 标记块，用户手写配置原样保留，首次写入自动备份为 config.gitglass.bak。私钥内容从不读取、展示、复制或记录。

09 刷新机制与性能

会触发刷新不会触发刷新
应用启动（一次）定时器 / 轮询
点「手动刷新」或 ⌘R应用切前后台
切换仓库 / 切换分支文件系统变化监听
写操作成功、遴选冲突失败后打字输入（历史搜索纯内存过滤）
点「深度搜索」、勾选「全部分支」窗口获得焦点 / 网络状态变化
一次刷新并行读取状态、分支、历史、远程源、储藏、标签、密钥；冲突文件列表仅在检测到「操作进行中」时才额外读取，正常仓库零额外进程。空闲时没有后台任务、没有循环动画；应用 footprint 约 38 MB 且长时间不增长。动画全部事件驱动，支持「减弱动态效果」与「降低透明度」。

11 故障排查

现象处理
提示「无法验证开发者」xattr -cr /Applications/GitGlass.app 或右键「打开」
「不是 Git 仓库」目录里没有 .git；用「新建仓库」初始化或重新选目录
推送被拒绝远程有新提交，先「拉取」再推送
SSH 认证失败确认公钥已加到平台账号、私钥存在且权限 600，点「测试连接」
提交按钮是灰的需要有已暂存文件 + 非空提交说明
切分支失败先提交或储藏当前改动
遴选后出现冲突面板用「采用当前分支 / 采用对方 / 已手动解决」逐个处理，再点「继续」；或「中止当前操作」
数据看起来没更新点「刷新」或切一次仓库 / 分支
Intel Mac 打不开 .app按第 1 章用源码在目标机器重建
构建报 sandbox-exec 错误使用脚本的 --disable-sandbox，或安装完整 Xcode

错误提示条给出中文原因与修复建议，展开「查看原始信息」可看 git 原始 stderr。

12 隐私与安全

项目做法
命令执行参数数组 + -- 分隔路径，绝不拼 shell 字符串
私钥不读取、不复制、不写日志、不随分发包传播
日志系统 os.Logger 结构化 JSON，私钥块与 token 参数脱敏
网络仅 git 同步与 ssh -T 测试；无统计上报
凭据不存储账号密码 / 令牌，认证交给系统 git / ssh-agent
危险操作删除、丢弃、遴选、还原均二次确认

13 开发者说明

分层

Views (SwiftUI)
   ↓ 只消费状态
AppState (@Observable @MainActor, 刷新编排)
   ↓
GitService / SSHKeyService (领域服务)
   ↓
CommandRunner (Process, 参数数组 + 临时文件输出 + 超时保护)

持久化用单个 JSON 文件，不引入数据库；错误用 AppError 类型化 + 中文恢复建议；Swift 6 严格并发；用 continuation 排队避免快速切仓库时刷新被丢弃。

自检

swift run --disable-sandbox GitGlassSelfTest
# 结果：129 通过，0 失败

在临时 Git 仓库与临时 SSH 目录上分 12 个章节覆盖状态、暂存、提交、历史搜索、遴选、还原、冲突检测与选边 / 继续 / 中止、储藏、标签、提交详情、中文空格路径、远程源、错误映射、持久化、密钥生成与权限、SSH config 幂等与备份、命令超时与并发、模型契约；不触碰用户真实 ~/.ssh。

扩展点

  • 新增 git 能力：GitService 加方法 → AppState 加 mutate 包装 → 页面加按钮。
  • 新增页面：AppTab 加 case → RootView 的 switch 加视图。
  • 刷新只在 AppState.refresh / mutate 触发，请勿引入 Timer。

在 GitHub 上维护

main 为受保护分支，改动走 PR。ci.yml 在 macos-26 runner 上跑编译、自检、静态检查与打包；release.yml 在推送 v* tag 时自动发布带分发 zip 的 Release。本地发版用 ./scripts/release.sh vX.Y.Z，贡献前读 CONTRIBUTING.md。
